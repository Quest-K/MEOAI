## 3. 상태 사전

### 3.1 고객 단위

**상담 상태 (3개)**

| 값 | 의미 |
|---|---|
| 상담대기 | 상담 시작 전. 신규 등록 고객 또는 재컨택 시기가 도래한 고객 |
| 상담중 | 상담·접수·지급·환수가 진행 중인 고객 |
| 상담종료 | 처리할 상품이 없는 고객. 반드시 잠재 또는 제외 |

**고객 구분 (3개 + 구분 없음)**

| 값 | 의미 |
|---|---|
| 가망 | 상담예약일이 없거나 기준일 + 3개월 이내 (바로 영업 대상) |
| 잠재 | 상담예약일이 기준일 + 3개월 이후 (나중에 다시 영업) |
| 제외 | 영업 대상이 아님. 제외 사유 필수 |
| (구분 없음) | 신규 등록 직후의 상담대기에서만 허용 |

**허용 조합**

| 상담 상태 | 허용되는 고객 구분 |
|---|---|
| 상담대기 | 구분 없음, 가망 |
| 상담중 | 가망, 잠재 |
| 상담종료 | 잠재, 제외 |

**제외 사유 (8개)**: 타사가입 · 기존유지 · 장기부재 · 신용불량 · 설치불가 · 오인입 · 타부서 · 기타
- `기타`는 메모 필수
- [확정] 타사가입·기존유지 → "약정 만료 예상일로 재영업 예약(잠재)" 전환을 제안
- [확정] 설치불가 → "다른 통신사 안내 여부를 확인했는지" 문구 표시

**상담예약일과 분류**
- 분류 기준일 = 오늘 + 가망 기준 개월 수 (기본 3개월, 설정값)
- 예약일이 없거나 기준일 이하 → 가망, 기준일 초과 → 잠재
- 제외 고객은 예약일이 없다 (제외 시 예약일 해제)

### 3.2 상품 단위

**상품 상태 (7개)**

| 값 | 의미 | 사유 |
|---|---|---|
| 상품제안 | 최종상품으로 확정했으나 접수 전 (현행 "작성중"에 해당) | - |
| 접수대기 | 접수를 진행 중 | - |
| 접수보류 | 접수를 잠시 멈춤 | 필수 (목록은 [미정] O-04, 현재 코드는 자유 입력) |
| 접수완료 | 접수가 끝남 (구 변경완료 포함) | - |
| 개통완료 | 개통까지 끝남. 고객지급이 `지급요청`으로 자동 설정됨 | - |
| 접수불가 | 외부 사유로 접수할 수 없음 | 신용불량 · 설치불가 · 기타 |
| 접수취소 | 고객 의사·변경으로 접수를 취소함 | 고객변심 · 상품변경 · 기타 |

- `기타` 사유는 메모 필수
- **접수불가 vs 접수취소 [확정]**: 접수불가는 신용·설치 등 외부 사유, 접수취소는 고객 의사. 제안 단계에서 고객이 거절하면 접수취소(고객변심)로 통일
- **일반 흐름**: 상품제안 → 접수대기 → (접수보류) → 접수완료 → 개통완료. 접수불가·접수취소는 어느 단계에서든 가능
- 단계 건너뛰기·역방향에 강제 제한은 두지 않음. 단, 개통완료·지급 이후 접수취소로 바꾸면 "환수 확인" 안내를 띄움
- **활성 상품** = 접수불가·접수취소가 아닌 상품

**상품 변경 [확정]**
1. [상품 변경] → 기존 행을 접수취소(사유 "상품변경")로 변경
2. 새 행 생성 + "변경 전 상품" 연결, 새 행은 `상품제안`으로 시작
3. 상담 상태를 상담중으로 변경 (R-02)
4. 기존 상품에 지급·환수 값이 있으면 환수 확인 안내

**고객지급**

| 값 | 의미 |
|---|---|
| (해당 없음) | 지급 대상 아님 또는 개통 전 |
| 지급요청 | 개통완료 시 자동 설정 |
| 지급제외 | 지급이 없는 상품 (부가상품 등). 개통완료되면 처리 끝으로 본다 (§13) |
| 지급보류 | 지급을 멈춤 |
| 지급완료 | 지급일 기록 필수 (기본값 오늘, 수정 가능 [제안]) |

**수수료 정산 (구 "지급계산서발행")** [확정: 상품건별, 발행 → 수금 순서]

| 값 | 의미 | 기록 값 |
|---|---|---|
| (해당 없음) | 정산 대상 아님 | - |
| 발행예정 | 세금계산서 발행 전 | - |
| 발행완료 | 세금계산서 발행함 | 발행일, 발행금액 |
| 수금완료 | 수금함 | 수금일, 수금금액 |

- `수금완료`는 `발행완료` 이후에만 선택 [제안]
- 수금금액 ≠ 발행금액이면 경고 [제안]
- 정산 시작 시점은 개통완료 이후로 가정 [미정 O-03]
- 정산은 상담 상태·상품 상태에 영향을 주지 않는 독립 기록 축
- 값 이름(발행예정 / 발행완료 / 수금완료)은 제안, 검토 후 확정

**환수**

| 값 | 의미 |
|---|---|
| (해당 없음) | 환수 없음 |
| 환수요청 | 환수를 요청함. 상담 상태가 상담중으로 (R-03) |
| 환수완료 | 환수 끝 (환수완료일 기록 [제안]) |

- 환수 계산서 흐름은 추후 [미정 O-02]. 이번 개편 화면·칼럼에서는 제외, 확정되면 같은 형식(상품건별, 처리일·금액)으로 추가
- 기존 환수보류·환수진행 값은 이전 시 `환수요청`으로 통합

### 3.3 계약 단위 (계산값, 읽기 전용)

소속 상품에서 위→아래 순서로 판정:

| 순서 | 조건 | 계약 상태 |
|---|---|---|
| 1 | 상품 없음 | - |
| 2 | 모든 상품이 접수불가·접수취소 | 취소 |
| 3 | 환수 값이 있는 상품이 있음 | 환수 |
| 4 | 활성 상품 중 지급 전(접수 이후 상품 또는 지급요청·지급보류)이 있음 | 진행 |
| 5 | 지급완료 상품이 있음 | 완료 |
| 6 | 그 외 | 제안 |

- 현행 `contracts`의 접수·지급·환수 상태 칼럼은 이전 후 사용하지 않음

### 4.1 고객부재 3회 (D-06)
- 연속 3회 부재 시 R-07. 고객과 연결되면 횟수 초기화

## 6. 지표 정의 (재집계 기준, D-09)

| 지표 | 정의 |
|---|---|
| 접수 이력 계약 | 소속 상품 중 하나라도 접수완료로 처음 바뀐 적이 있는 계약. 이후 취소돼도 유지 |
| 유치 건수 | 접수 이력 계약 수. 유치 고객 = 접수 이력 계약이 1건 이상인 고객 |
| 취소율 | 접수 이력 계약 중 현재 계약 상태가 "취소"인 계약 ÷ 접수 이력 계약. 일부 상품만 취소되고 나머지가 진행·완료이면 취소 아님 |
| 지급 현황 | 상품 단위 지급요청·지급보류·지급완료 건수와 금액 |
| 환수 현황 | 상품 단위 환수요청·환수완료 건수 |
| 정산 현황 | 발행예정·발행완료·수금완료 건수와 금액. 미수금 = 발행완료 금액 − 수금완료 금액 |
| 고객 현황 | 상담 상태별, 고객 구분별 분포. 제외는 사유별 |
| 재영업 | 상담예약일 도래 건수, 가망 전환 건수 |

- 접수완료 최초 시각 칼럼 필요 (코드의 `firstReceivedAt`). 이전 시 이력에서 채우고, 없으면 접수 상태 변경 기록 사용. 현행 `contracts.received_at`(계약 단위)이 이미 있어 **상품 단위로 확장**해야 함
- 이전 전 집계값은 스냅샷으로 보존하고 이전 후 값과 비교표 작성
- 현행 실적조회(`loadPerformanceData`)는 계약 기준(`is_acquired`, `received_at`) → 신규 정의로 교체 대상 (ST-F5)

## 7. 현행 구조와의 대응 (코드 확인 결과)

### 7.1 단위 차이 — 가장 큰 변경점

| 구분 | 현행 (CS.html 기준) | 신규 (상태사전 v2) |
|---|---|---|
| 고객 상태 | `customer_status` 5개 (상담대기·상담중·상담완료(=유치)·이탈·제외) + `consult_substatus`(상품안내·상담예약·고객부재) + `status_reason` | 상담 상태 3개 + 고객 구분 3개 + 제외 사유 8개 |
| 접수·지급·환수 | **계약 단위** (`contracts.contract_status/payout_status/clawback_status`) | **상품 단위** (지급·정산·환수) |

| 고객부재 횟수 | `customer_contacts` 행(1~3차) | `absenceCount` (코드 모델) |

### 7.2 이전 매핑표 초안 [제안] — ST-D2/D에서 확정

**고객**

| 현행 | 신규 |
|---|---|
| 상담대기 | 상담대기 + 구분 없음 |
| 상담중 (부가표시 없음/상품안내) | 상담중 + 상담예약일로 가망/잠재 분류 |
| 상담중·상담예약 | 상담중 + 예약일 기준 분류 |
| 상담중·고객부재 | 상담중 + 부재 횟수(컨택 이력 기준) |
| 상담완료(유치) | 지급이 모두 완료 → 상담종료 + 잠재(예약일은 D-03 기준 계산 필요) / 아니면 상담중 |
| 이탈·기존유지 / 타사가입 | 상담종료 + 제외(같은 사유) |
| 이탈·고객부재 | 상담종료 + 제외(장기부재) |
| 제외·오인입 / 타부서 | 상담종료 + 제외(같은 사유) |
| 제외·없는번호 / 테스트 | 상담종료 + 제외(기타) + 메모에 원래 사유 |

**상품** (계약 상태와 상품 진행 상태를 합쳐 판정)

| 현행 계약 상태 + 상품 진행 | 신규 상품 상태 |
|---|---|
| 작성중 | 상품제안 |
| 접수대기 | 접수대기 |
| 접수보류 | 접수보류 (사유 비어 있음 → 이전용 값 필요) |
| 접수불가 | 접수불가 (사유 기록 없으면 기타 + 메모) |
| 접수완료 + 설치대기 | 접수완료 |
| 접수완료 + 설치완료 | 개통완료 |
| 상품 진행 = 접수취소 | 접수취소 (사유 기타 + 메모, 고객변심/상품변경 구분 불가) |
| 계약의 지급 상태 | 소속 활성 상품 전체에 복제 (금액 분배는 N-03) |
| 계약의 환수 보류·진행 | 환수요청 |
