### 작업 규칙(사용자와 합의)
- 답변은 한국어, 끝나면 결과를 짧게 요약하고 파일 전달. 빠르게 진행, 추가 수정은 나중에 결정. 사용자가 "제안대로 진행"이라 하면 제안안으로 진행.
- **SQL은 작성만** 하고 사용자가 Supabase SQL Editor에서 실행. 운영 DB라 백업 → `begin; … commit;`, 확인 쿼리는 JSON 한 줄(에디터는 마지막 결과만 보여 줌).
- 기존 테이블·칼럼·함수는 **유지하고 추가만**(기존 함수 삭제 0을 매번 확인). 삭제는 G4 이후.
- 테스트가 필수가 아니면 건너뛰되, 운영 DB SQL·규칙 엔진·화면 변경은 가짜 DB 브라우저 테스트(Playwright + 메모리 가짜 supabase)로 확인. 실제 DB 확인은 사용자 몫.
- 단계가 끝날 때마다 §12 로그에 한 줄(6칸: 일시|작업 ID|내용|산출물|상태|다음), 이 문서 전달 시 파일 이름에 일시 8자리(월일시분) 붙임(§11). 자동 치환으로 행을 넣을 땐 반영 여부를 grep으로 확인.
- 테스트 고객 이름은 `(인생비서)테스트`. 정리 순서는 V2 완성 → 필요한 파일 보관(M8) → 삭제(M9). **지금은 삭제하지 않는다.**
- 새 JS를 파일 끝 `<script>`에 넣으면 시작 시 먼저 호출되는 함수에서 "not defined" 오류가 난다 → 선언부는 첫 인라인 스크립트 앞에 둔다.
