### 1-3. 렌탈 > 고객상담 MVP (선택지 화면)
- 위치: CS_v2.html 안의 `view-rental-cs` + `<script id="rental-mvp">` (이름은 rental/Rental/rtl 접두사)
- 선택 항목(7개)
  1) 상품: 정수기 / 비데 / 공기청정기 / 기타
  2) 회사: 코웨이 / 쿠쿠 / SK매직 / LG전자 / 교원웰스 / 청호나이스 / 기타
  3) 모델명: 상품+회사 선택 후 목록 선택 (목록이 비어 있으면 직접 입력)
  4) 약정기간: 3·4·5·6·7년 (상품·회사별 가능 기간만 활성)
  5) 관리방법: 자가관리 / 방문관리 (방문관리면 주기 2·4·6·8개월, 상품별 제한 가능)
  6) 타사보상: 해당없음 / 기존 회사
  7) 결합할인: 단독신청 / 신규결합 / 기존결합 (일부 타사보상과 중복 불가 → 경고 표시)
- 상품·회사를 바꾸면 모델명 초기화, 선택 불가가 된 약정기간·방문주기는 자동 해제
- 데이터 입력 위치: 스크립트 안 `RENTAL_DATA` (models / terms / visitCycles / blockedCombos) — DB 연결 후에는 DB에서 읽도록 교체
- 아직 없는 것: 요금·사은품·수수료 계산, 저장

### 1-4. 렌탈 DB 설계 (Supabase) — rental_schema.sql
- 원칙: 렌탈료·수수료·사은품은 **매월 변경** → UPDATE 하지 않고 적용월(`apply_month`, 매월 1일) 새 행 추가. 해당 월 행이 없으면 직전 월 값 유지. 현재값 = `apply_month <=` 이번 달(한국 기준) 중 가장 최근 행
- 계약 저장 시 `plan_id` + 그 시점 금액(렌탈료·수수료·사은품)을 계약 쪽에 복사해 과거 계약이 변하지 않게 함 (저장 기능 단계에서 반영)

| 테이블 | 용도 | 주요 칼럼 |
|---|---|---|
| rental_models | 모델 목록 | category, company, model_name, model_code, is_active, sort_order |
| rental_plans | 모델별 판매 조합 | model_id, term_years, care_type, visit_cycle_months, is_active |
| rental_plan_prices | 월별 렌탈료 | plan_id, apply_month, month_fee, reg_fee |
| rental_commissions | 월별 수수료(에이전시별) | plan_id, agency, apply_month, commission_amount |
| rental_gifts | 월별 사은품 | plan_id, apply_month, gift_amount, gift_note |
| rental_compensations | 월별 타사보상 | plan_id, prior_company, apply_month, benefit_amount |
| rental_combo_discounts | 월별 결합할인(신규/기존) | plan_id, combo_type, apply_month, discount_amount |
| rental_combo_rules | 결합할인↔타사보상 중복 불가 규칙 | company, prior_company, combo_type, apply_month, blocked |

- 뷰: `v_rental_price_now`, `v_rental_commission_now`, `v_rental_gift_now`, `v_rental_comp_now`, `v_rental_combo_now`, `v_rental_combo_rules_now`, 화면용 `v_rental_catalog_now`
- 화면 연결: 모델 목록 = category·company 별 model_name, 가능한 약정 = term_years, 방문주기 = 방문관리 행의 visit_cycle_months
- RLS: 현재는 로그인 사용자만 읽기·쓰기. 기존 관리자 판별 방식에 맞춰 조건 변경 필요, 수수료 표는 관리자 전용 권장
- 상태: SQL 문법 검사만 통과, **Supabase 실제 실행은 미확인**
