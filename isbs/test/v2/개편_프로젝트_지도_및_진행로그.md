## 2. 카테고리별 변경 내용

### 2.1 상태값 (흐름 ②)

| 대상 | 현재 | 변경 후 |
|---|---|---|
| 고객 | `customer_status` 5개 (상담대기·상담중·상담완료·이탈·제외) + 부가표시 | 상담 상태 3개 (상담대기·상담중·상담종료) + 고객 구분 (가망·잠재·제외·구분 없음) |
| 제외 사유 | 값이 제각각 | 8개 (타사가입·기존유지·장기부재·신용불량·설치불가·오인입·타부서·기타) |
| 상품 | `progress_status` 3개 (설치대기·설치완료·접수취소) | 7개 (상품제안·접수대기·접수보류·접수완료·개통완료·접수불가·접수취소) |
| 계약 | `contract_status` 저장 | 저장하지 않고 상품 상태에서 계산 (취소·환수·진행·완료·제안) |
| 지급 | 계약 단위 | 상품 단위 (지급요청·지급보류·지급완료) |
| 환수 | 계약 단위 (환수보류·환수진행) | 상품 단위 (환수요청·환수완료) |
| 수수료 정산 | 없음 | 신규, 상품건별 (발행예정·발행완료·수금완료). 값 이름은 N-07에서 확정 |

### 2.2 자동 규칙 (흐름 ②)

- 개통완료 → 지급요청 자동 설정 (R-01)
- 활성 상품이 모두 지급완료 → 상담종료 + 잠재, 재영업 예약일 자동 계산 (R-04)
- 연속 3회 부재 → 상담종료 + 제외(장기부재) 자동 처리 (R-07). 현재는 담당자 직접 이탈 처리
- 환수요청 → 상담중, 환수완료 후 종료 (R-03, R-05)
- 예약일 도래·기준 변경 → 분류 재계산 (R-08)
- 구현: `StatusRules.js` (테스트 68/68 통과). 화면 연결은 아직 없음
