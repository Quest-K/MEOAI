## 1. 고객 단위

### 1.1 상담 상태 (3개)

| 값 | 의미 |
|---|---|
| 상담대기 | 상담을 시작하기 전. 신규 등록 고객 또는 재컨택 시기가 도래한 고객 |
| 상담중 | 상담·접수·지급·환수가 진행 중인 고객 |
| 상담종료 | 처리할 상품이 없는 고객. 반드시 잠재 또는 제외 |

### 1.2 고객 구분 (3개 + 구분 없음)

| 값 | 의미 |
|---|---|
| 가망 | 상담예약일이 없거나 기준일 + 3개월 이내 (바로 영업 대상) |
| 잠재 | 상담예약일이 기준일 + 3개월 이후 (나중에 다시 영업) |
| 제외 | 영업 대상이 아님. 제외 사유 필수 |
| (구분 없음) | 신규 등록 직후의 상담대기에서만 허용 |

### 1.3 상태 조합

| 상담 상태 | 허용되는 고객 구분 |
|---|---|
| 상담대기 | 구분 없음, 가망 |
| 상담중 | 가망, 잠재 |
| 상담종료 | 잠재, 제외 |

### 1.4 제외 사유 (8개)

타사가입 · 기존유지 · 장기부재 · 신용불량 · 설치불가 · 오인입 · 타부서 · 기타

- `기타`는 메모 필수.
- [확정] 타사가입·기존유지를 선택하면 "약정 만료 예상일로 재영업 예약(잠재)" 전환을 제안한다.
- [확정] 설치불가를 선택하면 "다른 통신사 안내 여부를 확인했는지" 문구를 보여 준다.

### 1.5 상담예약일과 분류

- 분류 기준일 = 오늘 + 가망 기준 개월 수(기본 3개월, 설정값).
- 예약일이 없거나 기준일 이하 → 가망, 기준일 초과 → 잠재.
- 제외 고객은 예약일이 없다(제외 시 예약일 해제).

## 2. 상품 단위

### 2.1 상품 상태 (7개)

| 값 | 의미 | 사유 |
|---|---|---|
| 상품제안 | 최종상품으로 확정했으나 접수 전 (현행 "작성중"에 해당) | - |
| 접수대기 | 접수를 진행 중 | - |
| 접수보류 | 접수를 잠시 멈춤 | 필수 (목록은 [미정] O-04) |
| 접수완료 | 접수가 끝남 (구 변경완료 포함) | - |
| 개통완료 | 개통까지 끝남. 고객지급이 `지급요청`으로 자동 설정됨 | - |
| 접수불가 | 외부 사유로 접수할 수 없음 | 신용불량 · 설치불가 · 기타 |
| 접수취소 | 고객 의사·변경으로 접수를 취소함 | 고객변심 · 상품변경 · 기타 |

- `기타` 사유는 메모 필수.
- **접수불가 vs 접수취소 [확정]:** 접수불가는 신용·설치 등 외부 사유, 접수취소는 고객 의사. 제안 단계에서 고객이 거절하면 접수취소(고객변심)로 통일한다.
- **일반 흐름:** 상품제안 → 접수대기 → (접수보류) → 접수완료 → 개통완료. 접수불가·접수취소는 어느 단계에서든 가능.
- 목업 가정대로 단계 건너뛰기·역방향에 강제 제한은 두지 않는다. 단, 개통완료·지급 이후에 접수취소로 바꾸면 "환수 확인" 안내를 띄운다.
- **활성 상품** = 접수불가·접수취소가 아닌 상품.

### 2.2 상품 변경 [확정]

1. [상품 변경] 버튼 → 기존 행을 접수취소(사유 "상품변경")로 바꾼다.
2. 새 행을 만들고 "변경 전 상품"을 연결한다. 새 행은 `상품제안`으로 시작한다.
3. 상담 상태를 상담중으로 바꾼다(R-02).
4. 기존 상품에 지급 또는 환수 값이 있으면 환수 확인 안내를 띄운다.

### 2.3 고객지급

| 값 | 의미 |
|---|---|
| (해당 없음) | 지급 대상 아님 또는 개통 전 |
| 지급요청 | 개통완료 시 자동 설정 |
| 지급보류 | 지급을 멈춤 |
| 지급완료 | 지급일 기록 필수 (기본값 오늘, 수정 가능 [제안]) |

### 2.4 수수료 정산 (구 "지급계산서발행") [확정: 상품건별, 발행 → 수금 순서]

상위점으로부터 수수료를 받는 흐름. 상품 1건마다 기록한다.

| 값 | 의미 | 기록 값 |
|---|---|---|
| (해당 없음) | 정산 대상 아님 | - |
| 발행예정 | 세금계산서 발행 전 | - |
| 발행완료 | 세금계산서 발행함 | 발행일, 발행금액 |
| 수금완료 | 수금함 | 수금일, 수금금액 |

- 순서 검증: `수금완료`는 `발행완료` 이후에만 선택할 수 있다. [제안]
- 수금금액이 발행금액과 다르면 경고 표시. [제안]
- 정산을 시작할 수 있는 시점은 개통완료 이후로 가정한다. [미정] O-03
- 정산은 상담 상태·상품 상태에 영향을 주지 않는다 (독립 기록 축).
- 값 이름(발행예정 / 발행완료 / 수금완료)은 제안이며 검토 후 확정한다.

### 2.5 환수

| 값 | 의미 |
|---|---|
| (해당 없음) | 환수 없음 |
| 환수요청 | 환수를 요청함. 상담 상태가 상담중으로 바뀜 (R-03) |
| 환수완료 | 환수가 끝남 (환수완료일 기록 [제안]) |

- **환수 계산서 흐름은 추후 확인 [미정] O-02.** 이번 개편에서는 화면·칼럼 구현에서 제외하고, 확정되면 같은 형식(상품건별, 처리일·금액)으로 추가한다.
- 기존의 환수보류·환수진행 값은 이전 시 `환수요청`으로 통합한다.

## 3. 계약 단위 (계산값, 읽기 전용)

계약 상태는 소속 상품에서 위에서 아래 순서로 판정한다.

| 순서 | 조건 | 계약 상태 |
|---|---|---|
| 1 | 상품이 없음 | - |
| 2 | 모든 상품이 접수불가·접수취소 | 취소 |
| 3 | 환수 값이 있는 상품이 있음 | 환수 |
| 4 | 활성 상품 중 지급 전(접수 이후 상품 또는 지급요청·지급보류)이 있음 | 진행 |
| 5 | 지급완료 상품이 있음 | 완료 |
| 6 | 그 외 | 제안 |

- 현행 `contracts`의 접수·지급·환수 상태 칼럼은 이전 후 사용하지 않는다.

## 4. 자동 규칙 일람

모든 자동 변경은 이력에 "시스템"으로 기록한다.

| ID | 트리거 | 동작 |
|---|---|---|
| R-01 | 상품이 개통완료 | 고객지급이 해당 없음이면 지급요청으로 설정 |
| R-02 | [상품 변경] 시작 | 상담 상태를 상담중으로 |
| R-03 | 환수요청 | 상담 상태를 상담중으로 |
| R-04 | 지급완료 처리 후 활성 상품이 모두 지급완료 (환수 진행 중인 상품 없음) | 상담종료 + 잠재. 재영업 예약일 = 인터넷 최초 상품 지급완료일 + N년(1 또는 3년 선택). 예약일이 가망 기준 이내이면 기준일 + 3개월 + 1일로 보정 [제안] |
| R-05 | 환수완료 처리 후 환수 진행·지급 전 상품이 없음 | 상담종료. 기존 예약일이 유효하면 유지. 예약일이 없거나 가망 범위이면 상담종료 모달(잠재/제외)을 띄움 |
| R-06 | 제외 처리 | 상담종료 + 제외. 예약일 해제. 상품제안 상품은 접수불가로 자동 변경 (신용불량·설치불가는 그대로, 나머지는 사유 기타 + 메모 "상담 단계 제외(사유)") |
| R-07 | 고객부재 기록이 연속 3회 | 상담종료 + 제외(장기부재). 제외 해제 시 상담대기 + 가망으로 복귀 |
| R-08 | 상담예약일 도래, 기준 개월 수 변경, 예약일 수정·해제 | 분류 재계산. 상담종료 + 가망이 되면 상담대기로("재컨택 시기 도래"), 상담대기 + 잠재가 되면 상담중으로 |
| R-09 | 상담종료·제외 시도 | 활성 상품이 있고 전부 지급완료가 아니면 차단하고 "상품을 먼저 정리해 주세요" 안내 (제외는 상품제안 상품을 R-06으로 먼저 접수불가 처리한 뒤 검사) |
| R-10 | 제외 사유로 타사가입·기존유지 선택 | 약정 만료 예상일로 재영업 예약(잠재) 전환을 제안 |
| R-11 | 고객지급을 지급완료로 변경 | 지급완료일 기록 (기본 오늘) |
| R-12 | 상품제안 상태가 일정 기간 유지 | 업무 목록에 "제안 후 미진행" 표시. 기간은 설정값 [미정] O-05 |
| R-13 | 개통완료·지급 이후 상품을 접수취소로 변경 | 환수 확인 안내 표시 |

### 4.1 고객부재 3회 (D-06)

- 연속 3회 부재 기록 시 R-07 적용. 고객과 연결되면 횟수는 초기화한다.
- 현행 코드의 재안내 최대 횟수 설정을 3으로 맞춘다. 설정 위치 확인은 [미정] O-07.

## 5. 이력 기록 규칙

한 화면에 고객·상품 변경 이력을 통합해 보여 준다.

| 항목 | 설명 |
|---|---|
| 일시 | 변경한 날짜·시각 |
| 대상 | 고객 / 계약 / 상품 (상품이면 상품명) |
| 항목 | 상담 상태, 고객 구분, 상담예약일, 제외 사유, 상품상태, 고객지급, 수수료 정산, 환수 등 |
| 이전 값 → 변경 값 | 이전 값을 함께 기록한다 (목업은 변경 값만 기록) [제안] |
| 사유·메모 | 사유가 있는 변경에 기록 |
| 담당자 | 담당 상담원 또는 "시스템"(자동 변경) |

- 기본 화면은 최근 10건, 더보기로 전체 조회.

## 6. 지표 정의 (재집계 기준, D-09)

| 지표 | 정의 |
|---|---|
| 접수 이력 계약 | 소속 상품 중 하나라도 접수완료로 처음 바뀐 적이 있는 계약. 이후 취소돼도 유지 |
| 유치 건수 | 접수 이력 계약 수. 유치 고객 = 접수 이력 계약이 1건 이상인 고객 |
| 취소율 | 접수 이력 계약 중 현재 계약 상태가 "취소"인 계약 수 ÷ 접수 이력 계약 수. 일부 상품만 취소되고 나머지가 진행·완료이면 취소가 아님 |
| 지급 현황 | 상품 단위 지급요청·지급보류·지급완료 건수와 금액 |
| 환수 현황 | 상품 단위 환수요청·환수완료 건수 |
| 정산 현황 | 발행예정·발행완료·수금완료 건수와 금액. 미수금 = 발행완료 금액 − 수금완료 금액 |
| 고객 현황 | 상담 상태별, 고객 구분별(가망·잠재·제외) 분포. 제외는 사유별 분포 |
| 재영업 | 상담예약일 도래 건수, 가망으로 전환된 건수 |

- 접수완료 최초 시각을 기록하는 칼럼이 필요하다(이력만으로는 취소된 건을 소급할 수 없음). 이전 시 이력에서 채우고, 없으면 접수 상태 변경 기록을 사용한다.
- 지급·정산 금액의 원천 값(사은품·수수료 등)이 상품 단위로 있는지는 ST-C1에서 확인한다.
- 이전 전 집계값은 스냅샷으로 보존하고, 이전 후 값과 비교표를 만든다.
